# ODIN — Optical Dual-Spectrum Intelligence Node

Real-time **two-camera NDVI** terminal built on a Raspberry Pi, using nothing
more exotic than OpenCV and NumPy. No PyTorch, no YOLO, no model weights — the
signal comes from optical physics, not learned features.

```
NoIR camera (IR-cut removed)  ──►  red channel = visible red + NIR
USB webcam  (IR-cut intact)   ──►  red channel = visible red only
                                         │
                    align (homography H) ┘
                                         ▼
              NIR = max(Red_NoIR − k · Red_USB, 0)
              NDVI = (NIR − Red_USB) / (NIR + Red_USB)
                                         │
                                         ▼
                        false-colour heatmap → MJPEG → Flask dashboard
```

Healthy foliage reflects near-infrared strongly and absorbs visible red.
Anything that does *not* — bare soil, water, paint, synthetic fabric — drops
out of the index. That contrast is what growers use for crop stress, and it is
the same contrast that separates real vegetation from a background that has
been coloured to look like it.

## Repository layout

| Path | Purpose |
|---|---|
| `engine.py` | Pure NumPy/OpenCV maths: alignment, NIR isolation, NDVI, colour map, legend. No I/O — testable with no cameras. |
| `app.py` | Flask dashboard + MJPEG generators, sensor lifecycle, `/api/state`. |
| `calibrate.py` | ORB → BFMatcher → RANSAC homography, with pass/fail diagnostics. |
| `templates/index.html` | Dark-mode dashboard (zh-Hant / English). |
| `static/style.css` | Stylesheet. |
| `docs/LIGHTING.md` | **Read this before the demo** — NIR lighting, colour window, gain tuning. |

## Quick start

```bash
pip install -r requirements.txt

# 1. laptop smoke test (no second camera) — serves the dashboard, NDVI stays offline
python app.py --noir 0 --rgb 0

# 2. with both sensors
python app.py --noir 1 --rgb 0

# 3. register the sensors, then reload
python calibrate.py --noir 1 --rgb 0
python app.py
```

Dashboard defaults to `http://localhost:8080`.

## Honest states

The dashboard will not show you a plausible colour map when it does not have
one. Each degraded condition has its own badge:

| State | Meaning |
|---|---|
| `SINGLE SENSOR` | Only one camera opened. NDVI plate replaced with an explicit OFFLINE message. |
| `NOT CALIBRATED` | No `matrix_h.npy`. Streams are unregistered — smoke test only, not a reading. |
| `NDVI ONLINE` | Two sensors, homography loaded. |

`matrix_h.npy` is gitignored. It is per-unit (bracket, lens, sensor serial),
so it must be generated on the device it will run on.

## Why the colour window is `-0.2 … 1.0` and not `-1 … 1`

`cv2.applyColorMap(COLORMAP_JET)` puts **green** at its midpoint. Mapping the
full theoretical NDVI range lands bare soil (NDVI ≈ 0.0) on byte 127, which
renders green — i.e. it reads as "stressed vegetation". Starting the ramp at
`-0.2` pushes soil and water down into the blue end where an operator expects
them.

The legend is generated by sampling the *same* function the renderer uses
(`engine.legend()`), so the key cannot drift out of sync with the image.

## Known limitations

1. **Lighting.** White LEDs and fluorescents emit essentially no NIR beyond
   ~750 nm. Indoors under artificial light the NIR term collapses toward zero
   and everything reads NDVI ≈ −1 (dark blue), including healthy plants. Demo
   in daylight or add an 850 nm illuminator. See `docs/LIGHTING.md`.
2. **Homography vs parallax.** A homography maps one plane exactly. The two
   lenses sit ~2.5 cm apart, so 3D subjects carry parallax no `H` can remove.
   Accurate on the calibration target; degrades with depth.
3. **One scalar `k`.** The two sensors differ in quantum efficiency, Bayer dye
   transmission and lens transmission — a mismatch that is spectrally shaped,
   not constant. A single `k` tuned on a grey card holds only for that target
   under that illuminant.
4. **Radiometric clipping.** Pixels where the subtraction hits 0 report
   NDVI = −1, indistinguishable from real water. `engine.nir_valid_mask()`
   exposes where that happened; a mostly-empty mask means `k` is wrong or
   there is no NIR in the scene.
5. **No frame sync.** The USB webcam carries several frames of MJPEG
   encode/transfer/decode latency against a near-zero-latency CSI feed. Static
   subjects are fine; moving subjects produce colour fringes at the edges.

## Demo script

Place three targets in daylight, side by side:

1. **Live plant** → warm/red (NDVI > 0.5)
2. **Plastic plant or dry leaf** → green/blue (NDVI ≈ 0.1 – 0.3)
3. **Water or bare soil** → blue (NDVI < 0.1)

Then place the camouflaged object beside real foliage: real leaves sit at the
top of the scale, and anything painted or printed to imitate them does not
match in the near-infrared, so it drops toward the bottom.
